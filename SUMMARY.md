# Intervium — Detailed Summary

## What it is

**Intervium is an AI-powered interview-practice and career-prep platform.**
Candidates run realistic mock interviews tailored to a specific role, get every
answer scored by AI with actionable feedback, and work on the surrounding
job-hunt artifacts — CV/résumé optimization, ATS analysis, cover letters,
skill-gap tracking, and a coding-practice gym. It's a single, end-to-end
"interview prep, start to finish" product rather than a point tool.

It's built as a modern, production-shaped web app: **Next.js 16 (App Router) +
TypeScript (strict) + Tailwind v4 / shadcn/ui + Drizzle ORM over Supabase Postgres +
Auth.js v5**, with AI powered by **Groq model routing** (a fast model for
generation, a stronger model for judgment) and an optional DeepSeek provider.

---

## What it does — core capabilities

### 1. Tailored mock interviews
- An onboarding wizard builds a candidate profile; interview setup is wired
  entirely to **admin-managed content** (roles, specializations, seniority, tech
  stacks, focus areas, difficulty).
- Supports **text interviews** (answer in your own words) and **coding
  interviews** (solve problems in an in-browser **Monaco editor**), across
  **behavioral, system-design, and coding** tracks.
- A **single live interview per user** invariant keeps sessions clean (starting a
  new one non-destructively closes prior in-progress ones).

### 2. Cache-first question engine
- Questions are generated by Groq only when needed; a **sha256 "signature"** of
  (role + tech + focus + difficulty + interview type) keys a shared question
  pool, so identical configs reuse questions and the app leans on live AI less
  over time — cheaper and faster as it's used.

### 3. Instant AI scoring & feedback
- Each answer is scored the moment the interview finishes, with a **model answer,
  a rubric breakdown, per-question strengths/improvements, and an overall
  summary**.
- Scoring is **idempotent and budget-aware**: already-scored work is skipped, the
  AI budget is reserved before batch calls, and transient AI failures leave the
  session retryable rather than writing permanent fallback zeros.

### 4. CV / career workspace
- Import and edit a CV, **score it against ATS** (applicant-tracking systems),
  get **AI rewrite/optimization** suggestions, and **generate tailored cover
  letters**. Multiple CV design templates render identically in the on-screen
  preview and the downloaded PDF.

### 5. Code Dojo
- A personal coding gym with real problems, run against **test cases**, plus **AI
  hints** and **spaced repetition** that resurfaces problems you fumble.

### 6. Skill-gap analysis & study tools
- Cross-session **gap analysis** surfaces which topics drag scores down, with a
  focused learning path. A **Study** area captures notes, lets you **save weak
  answers as notes in one click**, and revises with **spaced-repetition
  flashcards** (with read-aloud).

### 7. Admin & operations
- A full **admin panel** with CRUD for roles, focus areas, tech stacks, access
  codes, questions, AI models, settings, and users — so the product can be
  **reconfigured without a redeploy**.
- An admin-only, environment-gated **QA Center** diagnostics dashboard, plus **AI
  usage** monitoring.

## What it achieved / what's notable

- **Production-grade engineering discipline.** Strict TypeScript with zero `any`,
  zod validation on all inputs, a green CI gate (type-check + lint + format +
  build), and a clear layered architecture (page → thin server action → service →
  AI/data).
- **Security by construction.** Authorization is **per-request**: every server
  action and API route re-checks the user and **scopes queries by `userId`**
  (IDOR-safe) — middleware is treated as convenience, not the gate. Access-code-
  gated registration, JWT sessions, bcrypt. AI output is zod-validated and
  React-escaped (no `dangerouslySetInnerHTML`/`eval`); untrusted CV/JD/answer text
  enters prompts as data, not instructions.
- **Cost & reliability controls for AI.** A **daily AI budget** and **rate
  limiting** guard spend; **batch scoring** minimizes calls; the signature cache
  continuously reduces reliance on live generation.
- **Operational flexibility.** Admin-managed content means roles/questions/timers
  change live; deploys to **Vercel + Supabase**, and fails fast at boot if required
  env vars are missing.
- **Free, open source, and self-hostable** positioning.

## Tech stack

| Concern | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router) — Server Components + Server Actions |
| Language | TypeScript (strict), types inferred from zod where possible |
| Question generation | Groq `llama-3.1-8b-instant` (fast, cache-friendly) |
| Scoring & CV AI | Groq `llama-3.3-70b-versatile` (stronger judgment) |
| Database | Supabase Postgres + Drizzle ORM (single node-postgres `pg` pool for queries and transactions) |
| Auth | Auth.js v5 — Credentials + JWT, role on the session |
| UI | Tailwind v4 + shadcn/ui, light/dark, brand green `#00B775` |

---

## Architecture (layering)

```
Route / Page (src/app/**)            server components fetch data, render client islands
  → Server Action (src/lib/actions)  'use server' — validate (zod) + authorize + orchestrate
    → Service / domain (src/lib/**)   business logic: scoring, question-engine, gap-analysis…
      → AI client (src/lib/ai/**)     Groq/DeepSeek HTTP, retry/timeout, prompt building
      → Data access (Drizzle + @db)   parameterized queries; withTransaction for multi-table writes
```

---

## Honest gaps (tracked debt)

From the project's own audit docs: **no automated test framework yet**; rate
limiting is in-process (a shared store like Redis/Upstash is the planned upgrade
for serverless); and **observability/error tracking** (Sentry/OTel, structured
logging) is still to be added.
